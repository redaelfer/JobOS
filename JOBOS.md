# JobOS: junior software engineering job search

JobOS helps a junior software engineer find LinkedIn, Indeed and official employer job offers, identify a person or published recruitment address to contact, and prepare a truthful CV and email for each opportunity. It keeps the whole workflow in one local workspace.

## Main workflow

The optional [FreeLLMAPI gateway](FREELLMAPI.md) connects downloaded Ollama or explicitly chosen upstream providers to JobOS and separate Codex/Claude Code launchers. Direct Ollama remains available without the gateway. JobOS web retrieval remains a separate source setting; no gateway setup or coding launch starts a job search.

For local generation from discovery/contact research through CV/email drafting, follow [LOCAL-AI-WORKFLOW.md](LOCAL-AI-WORKFLOW.md). AI models offers downloaded Ollama, optional local SearXNG setup, separate Groq/OpenRouter generation profiles and Tavily search, with API-key entry inside the app. New workspaces use local generation and key-free public search; explicit saved choices are preserved. Selecting a hosted model is always an explicit action and changes where CV/job inputs are processed.

1. Choose a provider in **AI models**: Codex, Gemini, Kimi, local Ollama or a compatible API. Save and test the model; configure a live search source when using a provider other than Codex. For generation without hosted quotas, download Ollama/Qwen3 and click **Use local model + public search**; this selects public LinkedIn/web sources without API keys. Websites can still restrict access. See [AI-MODELS.md](AI-MODELS.md) and [LOCAL-SETUP.md](LOCAL-SETUP.md). Save the current CV in **CV & AI ranking** and keep the original LaTeX template in the project's `main.tex` through **CV & email tailoring**. When experience changes, update both sources; the template is authoritative for tailored documents.
2. Set professional domains in **Job search**. The current selection is AI engineering, Machine learning, Data science and Full-stack development. Searches cover English and French titles for each field. General titles are included alongside junior variants, and all four fields get an early search query. You can add other fields in the saved preferences. A Closed decision applies only to that posting; a distinct posting ID at the same company is eligible even with the same title. Locations remain Morocco and remote roles. The search checks country eligibility rather than treating every remote job as worldwide.
3. Ask Codex to search or click **Search now**. Searches run only on request; the hourly schedule is disabled. It uses the current saved preferences and **Posted within** window (default last 30 days), deduplicates source URLs, and prioritizes domain-relevant postings whose publication date is confirmed on the source. **Broader coverage** is enabled by default: a second sequential pass looks for readable older or undated postings that may still be hiring. They need a source-confirmed title/company and full description, and cannot be explicitly closed or expired. They are retained for availability review, never presented as fresh or confirmed open. It checks readable public LinkedIn, Indeed and official employer postings, researches new and saved employers, and refreshes CV comparisons when their inputs change. There is no fixed number of jobs per search. Employer research and CV comparisons run sequentially in batches until all eligible returned records have been processed.
4. Open **Applications**. List view is the default. Each row includes its posting link, contact evidence, stage, publication text and **Tailor CV & email**. All saved opportunities remain visible; the fit threshold labels strong matches without hiding lower scores. Board view is still available.
5. Review the contacts. Prefer published recruiting emails. If none is confirmed, use a public recruiter/HR profile or the confirmed company application page. Evidence does not establish current affiliation or email delivery. JobOS never constructs guessed email addresses.
6. Select an opportunity in **CV & email tailoring**, choose French or English and click **Analyze offer first**. Review the key requirements, quoted offer/CV evidence, gaps and separate CV/email priorities. Then check the recipient and click **Tailor CV & write email**. Direct drafting also runs this analysis first when no current analysis is selected. Download the CV source/PDF, email and review notes, check the facts and layout, then send the application yourself.
7. Move the opportunity through Saved, Applied, Screening, Interview, Offer or Closed and schedule a follow-up when useful.

## One search for LinkedIn and Indeed

Click the single **Search now** button in Applications, Daily opportunities or Search history & employers. It searches LinkedIn and official employer pages, then Indeed, sequentially within one workflow. It runs only on request and reuses your saved CV, domains, experience level, Morocco/remote preferences, exclusions, publication window and broader-coverage choice. The **Job search** page saves edited preferences before starting that same combined search. Readable, verified offers are deduplicated before employer/contact research and CV comparisons, so those steps run once across the combined results. If one source fails, results from the other are retained with a coverage warning. Both-source failure is reported as a failed scan. Contacts appear on the opportunity, and **Tailor CV & email** works with the same saved records.

With the installed JobOS SearXNG service selected, Search now starts Docker Desktop on Windows and the owned container when needed, then continues the same guarded workflow. Startup progress is visible and failure gives an actionable report. Initial installation remains in AI models. Custom ports remain user-managed, and other search sources do not start Docker. Opening the app alone never starts a search or these services.

No Indeed application installation, account pairing or Indeed API key is required. Codex uses its built-in search; other models use the live search source saved in AI models. The no-key public sources request Indeed listings directly during the Indeed step. Configured search APIs find indexed Indeed URLs, but each posting still needs a readable description and source evidence. An API search success does not establish posting-page access. Verification pages, HTTP blocks and unsupported layouts produce coverage warnings; unverified offers are not saved. No challenge is bypassed. **Test live search** tests the configured service, not every Indeed page.

**Ollama web search HTTP 429** concerns the hosted search API on ollama.com, separately from the downloaded local model. Results found before the limit are kept; Indeed and recruiting-contact research may be incomplete. Reports show a shared source error once, with each source's coverage separately, including older reports. A blocked API is not repeatedly requested within that workflow. The error does not identify a reset time. To avoid that hosted quota, keep Ollama as the model and select **AI models → Live search source → Public LinkedIn + web · no API key**, then **Save AI settings** and **Test live search** before your next manual search. Public sites may still restrict access. JobOS does not change providers or retry automatically.

Regional, tracking and selected-job links with the same Indeed `jk`/`vjk` key share a posting identity. Deleting one prevents its variants from being recreated, including late search results and legacy saved dismissal URLs. Rediscovery preserves closed applications, stages and notes. Different Indeed keys and separate LinkedIn/employer postings remain distinct even when their company/title match. Searches impose no fixed total result count; source/provider limits still apply.

## Newest offers first

In **Applications**, choose **Publication → Last 24 hours / Last 7 days / Last 14 days / Last 30 days** to filter by the source's posting date. **Sort → Latest posted** puts the newest known publication date first. These filters work in list and board views and combine with stage/text filters. **All saved** is the Applications default and keeps older, closed and lower-fit records available; **Date unconfirmed** isolates offers whose publication date is missing. The same explicit publication windows are available in Daily opportunities. Discovery date is not used as a substitute for a missing publication date.

Applications and Daily opportunities default to **Latest posted**, using dates published by the source. Relative dates are approximate; missing dates appear last and never imply a new posting. **Recently detected** sorts when JobOS found the offer; **Best CV fit** sorts current comparisons first. A job found today may have been published months ago. Daily opportunities opens with **Publication: Last 30 days** (or your saved shorter window). The **Also worth checking** panel highlights older saved postings and postings with no confirmed date. Use its review buttons or **Publication → Older — check availability / Date unconfirmed** to review them. **All saved** retains the full history. Turn off **Broader coverage** in Job search if you want future discovery restricted to recent postings. Detection-date and strong-match filters remain available. Recently detected never means recently posted.

## Deleted and closed offers

Deleting an offer removes it from the workspace and remembers its canonical posting URL in the local database. Future searches, late results from an already-running search, email imports, Chrome capture and manual saves skip that posting instead of recreating it. Alternate LinkedIn links for the same numeric posting ID match the same remembered offer. Previously deleted results in old search reports are labeled and have no Save action. The memory survives a restart and is included in workspace exports; it stores only the URL and deletion date, not the deleted description or CV.

In **Applications**, click **Close** below the Stage menu (or on a board card or in opportunity details) for an offer you are not interested in, that is outside your field or whose eligibility does not fit. This sets its stage to **Closed** immediately, keeping its current record and notes. Closing removes the posting from Daily opportunities and matching alerts. Future searches skip its canonical posting URL, including tracking-link variants and results that arrive after you close it. Capture and email import also leave the closed record intact. You can reopen it yourself with the **Stage** menu; **All saved** keeps closed offers visible. Distinct posting IDs/URLs remain separate opportunities, even when the employer and title are the same; the app does not guess that different postings are duplicates. An offer with no URL cannot be reliably remembered by posting identity. Deletions made before this feature have no saved deletion memory and cannot reliably be reconstructed.

## Preserve the CV template

Offer analysis reads the full description already saved in JobOS, before generating CV edits or an email. It highlights up to six important requirements, separating required/preferred/unclear priorities and supported/partial/missing/uncertain CV evidence. Offer quotations are checked against the saved description. Candidate quotations are checked against the current master text and supporting saved CV; facts found only in the supporting CV remain uncertain until reconciled with the master. Unsupported claims receive clarification guidance rather than instructions to invent experience. Source excerpts establish what the documents say, not that a qualification fully satisfies a requirement; review the AI interpretation and eligibility yourself.

Analysis-only runs create no CV/email files. Their evidence is available in the protected draft details, and they appear as **Analysis** in history. Current analyses are reused for writing; changed master/CV text, job details, language or model trigger a fresh analysis. A valid analysis can remain available if subsequent drafting fails. The app exposes separate analysis/writing phases, and shares the same single-workflow guard. No new job search or outreach is triggered by analysis.

The supplied template is saved as the master `main.tex`. AI returns plain text replacements for existing text positions, not a new LaTeX document. JobOS applies those replacements to the original source, preserving the preamble, packages, colors, fonts, margins, commands, comments, spacing, hyperlinks, section order, bullet structure and tables. Invalid slot IDs, duplicate replacements and LaTeX commands in replacements are rejected.

The master is never overwritten by a tailored result. Each result is saved under `data/applications/<draft-id>/`; master changes have backups under `data/applications/master-backups/`. Changing the master marks earlier drafts as needing review. Manual edits remain possible. Text changes can affect line wrapping and page count, so a compiled PDF still needs a visual check; the app does not shrink fonts or change margins to force a fit.

## Check a running task

The status panel on every page identifies the active task (search, CV comparison, CV draft or local-model download), its provider/model, current workflow step, elapsed minutes and last successful status check. A full scan can take more than ten minutes because discovery, source checks, employer research and comparisons run sequentially. Codex uses a separate non-interactive CLI process; other providers use their API or local model server. These tasks do not call this chat, and you can continue chatting while the app works. Use **View details** for the report or **Refresh status** for a read-only check that preserves edited form fields. The app warns when it cannot reach the local server, disables new AI workflows until the status is known, and retries automatically. A successful status check confirms the server responded; it does not prove the provider is making progress. Provider changes and model downloads share the workflow guard. Hourly searches remain disabled.

## Honest limits

On-demand public searches have no result-count quota, but time, provider output and source access still limit coverage. They cannot guarantee every opportunity or real-time detection and may miss private or inaccessible postings. Relative posting dates and repost ages are approximate; they do not prove the date a vacancy was originally opened. An accessible page or Apply button does not prove that the vacancy remains open. Fit scores are explained estimates, not ATS results or hiring probabilities. Search queries exclude CV text and candidate contact details. Draft generation and ranking use the selected model: a configured local Ollama server or the chosen hosted provider. Alternative providers do not consume Codex usage and have their own access/quotas; failures never silently fall back. No emails or applications are sent automatically.
