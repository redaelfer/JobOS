# JobOS: junior software engineering job search

JobOS helps a junior software engineer find LinkedIn, Indeed and official employer job offers, identify a person or published recruitment address to contact, and prepare a truthful CV and email for each opportunity. It keeps the whole workflow in one local workspace.

## Main workflow

The optional [FreeLLMAPI gateway](FREELLMAPI.md) connects downloaded Ollama or explicitly chosen upstream providers to JobOS and separate Codex/Claude Code launchers. Direct Ollama remains available without the gateway. JobOS web retrieval remains a separate source setting; no gateway setup or coding launch starts a job search.

For local generation from discovery/contact research through CV/email drafting, follow [LOCAL-AI-WORKFLOW.md](LOCAL-AI-WORKFLOW.md). AI models offers downloaded Ollama, optional local SearXNG setup, separate Groq/OpenRouter generation profiles and Tavily search, with API-key entry inside the app. New workspaces use local generation and key-free public search; explicit saved choices are preserved. Selecting a hosted model is always an explicit action and changes where CV/job inputs are processed.

1. In **Settings → Search preferences**, save your domains, experience level, location and date window once. A new workspace starts with data science, ML, AI engineering, full-stack and data engineering; graduate/entry level; Morocco and eligible remote roles; and 30 days. Existing preferences are kept.
2. Open **Offers** and click **Search now**. No CV is needed and searches are manual. Verified batches appear as they arrive. Choose **New in last search** to isolate what was actually added. If a source fails, retry just that source; its results join the original search. There is no result quota. Older/undated postings are marked for availability review; an unknown date is not a new publication.
3. Read the posting, keywords and contact evidence. Published recruiting addresses appear first. Employer lookup runs separately. A general business address, a contact published for an earlier vacancy, or an unconfirmed professional profile is not a verified HR email.
4. For a role you want, click **Tailor CV & email**. Save your accurate master `main.tex` once via **Settings → Master main.tex & drafts**. JobOS analyzes the requirements and drafts using this master, without a second CV upload. The offer language is selected by default (French/English); change it if needed. Review the separate CV and use **Copy recipient**, **Copy subject** and **Copy body**. Nothing is sent automatically.
5. Use **Close** to skip an offer. Use **Check saved offers in browser** to find postings that explicitly stopped accepting applications. Review each notice and link, then select **Move to Expired** or **Expire all confirmed**. See archived postings with **Stage → Expired**. The archive keeps contacts, notes and drafts; jobs you already applied for also keep their application stage. A different posting from that employer can still appear.

## One search for LinkedIn and Indeed

Discovery checks LinkedIn/company careers and Indeed. Each verified batch is saved before waiting for another source. Employer research uses a persistent queue; search does not read your CV or trigger scoring. A healthy search with zero new roles is distinct from incomplete coverage.

With the installed JobOS SearXNG service selected, Search now starts Docker Desktop on Windows and the owned container when needed, then continues the same guarded workflow. Startup progress is visible and failure gives an actionable report. Initial installation remains in AI models. Custom ports remain user-managed, and other search sources do not start Docker. Opening the app alone never starts a search or these services.

Indeed defaults to **Chrome session** mode. Reload JobOS extension **0.4.1+** at `chrome://extensions`, refresh JobOS in that Chrome profile, and click Search now. LinkedIn/company careers run first using the configured search source. Then the extension opens an Indeed controller and one temporary browsing tab. It uses the same saved domains, level, location, exclusions and date window, follows available pagination, and saves matching readable descriptions as they arrive. No model or CV is used for this browser step. Public role queries are sent to Indeed; browser cookies stay inside Chrome.

Keep Chrome, JobOS server and the controller tab open. First use asks you to allow access to ma.indeed.com and www.indeed.com. If Indeed needs verification or login, the scan pauses: open its tab, handle it yourself, and Resume. An unsupported page is also paused; you can skip that page (reported as incomplete) or stop Indeed and keep the results. Paused searches release the AI workflow lock, retain their cursor across server restarts, and cannot be started twice. Resume a restarted run from JobOS. While Indeed is paused, **Start a new search** ends that step and starts a fresh LinkedIn-first run without removing saved offers or contacts. Unsupported layouts report missing fields separately from actual verification/sign-in requests. Manual extension capture also supports both current and legacy Indeed posting layouts. No CAPTCHA is solved, no challenge is bypassed, and a browser session cannot guarantee access.

**Settings → Search preferences → Indeed search connection** lets you explicitly choose the older configured-provider/server mode. APIs can discover indexed URLs but do not guarantee readable Indeed pages. Check Indeed browser setup verifies extension presence only; it does not establish live posting access. The general Test live search checks the configured search service separately.

The same form offers **Indeed opportunities → Morocco roles + junior remote**. This uses the saved domains for broad Morocco title searches (a title need not say junior), excludes explicit advanced/senior titles and recognized minimum-experience requirements, and searches remote roles with junior/graduate terms. Both browser and provider results use the same filter: remote roles outside Morocco need junior-level evidence and must not have a recognized restriction excluding Morocco. Unknown remote eligibility is labeled for review. A missing location from a Morocco browser search is retained with an explicit location warning; a regional Indeed URL alone is not country evidence. This is a text-based filter, not a hiring-eligibility guarantee; incomplete or unusual wording can be missed. Saving applies to the next manual search, keeps existing offers and contacts, and does not change LinkedIn preferences or manual capture. General preferences remain available as the alternative.

**Ollama web search HTTP 429** concerns the hosted search API on ollama.com, separately from the downloaded local model. Results found before the limit are kept; Indeed and recruiting-contact research may be incomplete. Reports show a shared source error once, with each source's coverage separately, including older reports. A blocked API is not repeatedly requested within that workflow. The error does not identify a reset time. To avoid that hosted quota, keep Ollama as the model and select **AI models → Live search source → Public LinkedIn + web · no API key**, then **Save AI settings** and **Test live search** before your next manual search. Public sites may still restrict access. JobOS does not change providers or retry automatically.

Regional, tracking and selected-job links with the same Indeed `jk`/`vjk` key share a posting identity. Deleting one prevents its variants from being recreated, including late search results and legacy saved dismissal URLs. Rediscovery preserves closed applications, stages and notes. Different Indeed keys and separate LinkedIn/employer postings remain distinct even when their company/title match. Searches impose no fixed total result count; source/provider limits still apply.

Indeed results pages may add `vjk` when a preview is selected. This is accepted as the same listing search; the server still checks the region, query, location, date/sort filters and page offset. Captured vacancies keep a direct `/viewjob?jk=...` offer link instead of the search-results URL.

## Newest offers first

In **Applications**, choose **Publication → Last 24 hours / Last 7 days / Last 14 days / Last 30 days** to filter by the source's posting date. **Sort → Latest posted** puts the newest known publication date first. These filters work in list and board views and combine with stage/text filters. **All saved** includes every publication date within the selected stage; **Date unconfirmed** isolates offers whose publication date is missing. The same explicit publication windows are available in Daily opportunities. Discovery date is not used as a substitute for a missing publication date.

The Offers inbox opens with **Publication → All saved**, **Sort → Recently detected** and **Stage → Saved**. Publication filters use source dates. Use **More** for the board, manual ranking, historical reports and follow-ups.

## Deleted and closed offers

In the Chrome profile where you use LinkedIn, open **Daily opportunities** or **Applications** and click **Check saved offers in browser**. Reload version 0.3 of the unpacked JobOS extension at `chrome://extensions` and refresh JobOS after updating. The extension asks for access to the sites of the saved postings when needed. Keep its review tab open. It opens each linked posting not already closed or marked expired in a temporary tab in that profile, waits for the job details to render, and reads the application notice. Review each reported closure with its original wording and posting link, then choose **Move to Expired** or **Expire all confirmed** if appropriate. Blocked or unreadable offers have manual review links. A missing closure notice leaves hiring status unconfirmed. An interrupted browser run can be continued from the same button. Earlier public-page reports are labeled separately.

Deleting an offer removes it from the workspace and remembers its canonical posting URL in the local database. Future searches, late results from an already-running search, email imports, Chrome capture and manual saves skip that posting instead of recreating it. Alternate LinkedIn links for the same numeric posting ID match the same remembered offer. Previously deleted results in old search reports are labeled and have no Save action. The memory survives a restart and is included in workspace exports; it stores only the URL and deletion date, not the deleted description or CV.

In **Applications**, click **Close** below the Stage menu (or on a board card or in opportunity details) for an offer you are not interested in, that is outside your field or whose eligibility does not fit. This sets its stage to **Closed** immediately, keeping its current record and notes. Closing removes the posting from Daily opportunities and matching alerts. Future searches skip its canonical posting URL, including tracking-link variants and results that arrive after you close it. Capture and email import also leave the closed record intact. Choose **Closed** or **All stages** in the stage filter to find the offer and reopen it with its **Stage** menu. Distinct posting IDs/URLs remain separate opportunities, even when the employer and title are the same; the app does not guess that different postings are duplicates. An offer with no URL cannot be reliably remembered by posting identity. Deletions made before this feature have no saved deletion memory and cannot reliably be reconstructed.

## Preserve the CV template

Offer analysis reads the full description already saved in JobOS, before generating CV edits or an email. It highlights up to six important requirements, separating required/preferred/unclear priorities and supported/partial/missing/uncertain CV evidence. Offer quotations are checked against the saved description. Candidate quotations are checked against the current master text only. Unsupported claims receive clarification guidance rather than instructions to invent experience. Source excerpts establish what the documents say, not that a qualification fully satisfies a requirement; review the AI interpretation and eligibility yourself.

Analysis-only runs create no CV/email files. Their evidence is available in the protected draft details, and they appear as **Analysis** in history. Current analyses are reused for writing; changed master text, job details, language or model trigger a fresh analysis. A valid analysis can remain available if subsequent drafting fails. The app exposes separate analysis/writing phases, and shares the same single-workflow guard. No new job search or outreach is triggered by analysis.

The supplied template is saved as the master `main.tex`. AI returns plain text replacements for existing text positions, not a new LaTeX document. JobOS applies those replacements to the original source, preserving the preamble, packages, colors, fonts, margins, commands, comments, spacing, hyperlinks, section order, bullet structure and tables. Invalid slot IDs, duplicate replacements and LaTeX commands in replacements are rejected.

The master is never overwritten by a tailored result. Each result is saved under `data/applications/<draft-id>/`; master changes have backups under `data/applications/master-backups/`. Changing the master marks earlier drafts as needing review. Manual edits remain possible. Text changes can affect line wrapping and page count, so a compiled PDF still needs a visual check; the app does not shrink fonts or change margins to force a fit.

## Check a running task

The status panel on every page identifies the active task (search, CV comparison, CV draft or local-model download), its provider/model, current workflow step, elapsed minutes and last successful status check. A full scan can take more than ten minutes because discovery, source access and verification can take time. Codex uses a separate non-interactive CLI process; other providers use their API or local model server. These tasks do not call this chat, and you can continue chatting while the app works. Use **View details** for the report or **Refresh status** for a read-only check that preserves edited form fields. The app warns when it cannot reach the local server, disables new AI workflows until the status is known, and retries automatically. A successful status check confirms the server responded; it does not prove the provider is making progress. Provider changes and model downloads share the workflow guard. Hourly searches remain disabled.

## Honest limits

On-demand public searches have no result-count quota, but time, provider output and source access still limit coverage. They cannot guarantee every opportunity or real-time detection and may miss private or inaccessible postings. Relative posting dates and repost ages are approximate; they do not prove the date a vacancy was originally opened. An accessible page or Apply button does not prove that the vacancy remains open. Fit scores are explained estimates, not ATS results or hiring probabilities. Search queries exclude CV text and candidate contact details. Draft generation and ranking use the selected model: a configured local Ollama server or the chosen hosted provider. Alternative providers do not consume Codex usage and have their own access/quotas; failures never silently fall back. No emails or applications are sent automatically.
