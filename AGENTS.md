# JobOS project instructions

The product goal is to help a junior software engineer discover LinkedIn and official employer job offers, preferably newest first, find published recruitment contacts, and prepare a tailored CV and unsent HR email. Read JOBOS.md for the workflow and boundaries.

- Applications should open in list view and offer a direct posting link and CV/email preparation for each opportunity. Keep all saved offers visible; a fit threshold should label recommendations rather than discard records.
- Run job searches only when the user explicitly asks or clicks Search now. The hourly schedule is disabled; ignore old heartbeat requests. There is no fixed number of search results. Prioritize source-confirmed postings within the chosen window (default last 30 days), newest first. Broader coverage is enabled by default: perform a second sequential pass for readable, domain-relevant older or undated postings not marked closed, retain them for availability review, and never call them fresh or confirmed open without current evidence. Preserve saved records and label source uncertainty. No search can guarantee exhaustive coverage.
- Use the current saved professional domains, Morocco/remote preferences, CV, exclusions and experience level. Distinguish posting date from discovery date, flag country eligibility uncertainty, deduplicate URLs, and preserve user records.
- Preserve dismissedJobs records when an offer is deleted. All ingestion and discovery paths must skip its canonical URL/LinkedIn posting ID, including results returning after deletion and after a restart. Rediscovery must retain a closed application's ID, stage and notes. Do not suppress distinct posting IDs merely because their company/title match. Applications defaults to All saved with optional source-publication filters and Latest posted sorting.
- For every future CV created in this workspace, use the current project-root main.tex as the template and change only text. Preserve its packages, preamble, commands, colors, fonts, margins, spacing, hyperlinks, section order, bullets and tables. Do not simplify or redesign the format unless the user explicitly requests that change. Keep the master intact, save tailored results separately, compile when possible and visually review the PDF.
- Preserve actual candidate facts. Never invent qualifications, achievements, HR names, affiliations or email addresses. Keep source evidence and honest uncertainty for public contacts and vacancies.
- Do not send messages or apply to jobs automatically. Generated outreach remains an editable draft for the user to send.
- Keep CV contents, tokens and credentials out of logs and public search queries. Private master/source files, the database and generated packages belong in ignored locations.
- Test substantive behavior changes with the isolated suite and verify interface changes in the browser. Run npm run check. Document live checks and material limitations in TESTING.md. Avoid concurrent Codex search/ranking/tailoring workflows.
